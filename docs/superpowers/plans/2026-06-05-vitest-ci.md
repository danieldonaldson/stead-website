# Vitest + GitHub CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Vitest component render tests for all pages and components, and a GitHub Actions CI workflow that runs type-checking, build verification, and tests on every push/PR to main.

**Architecture:** Vitest is configured via `getViteConfig` from `astro/config`, which reuses the existing Astro/Vite config. Tests use the Astro Container API to render components server-side and assert on the returned HTML string. CI runs as a single job with two sequential steps: build then test.

**Tech Stack:** Vitest 3.x, Astro Container API (`astro/container`), GitHub Actions

---

## File Map

| File | Action | Purpose |

**Files:**

- Create: `vitest.config.ts`

- [ ] **Step 1: Install vitest**

```bash
pnpm add -D vitest
```

Expected output: vitest added to `devDependencies` in `package.json`.

- [ ] **Step 2: Add test script to package.json**

In `package.json`, add `"test": "vitest run"` to the `"scripts"` block:

```json
"scripts": {
  "dev": "astro dev",
  "start": "astro dev",
  "build": "pnpm compile:css && astro check && astro build",
  "compile:css": "sass assets/scss/now-ui-kit.scss public/css/now-ui-kit.css && cp assets/css/stead.css public/css/stead.css",
  "preview": "astro preview",
  "astro": "astro",
  "test": "vitest run"
},
```

- [ ] **Step 3: Create vitest.config.ts**

Create `vitest.config.ts` at project root:

```ts
import { getViteConfig } from 'astro/config';

export default getViteConfig({
  test: {
    include: ['src/tests/**/*.test.ts'],
  },
});
```

`getViteConfig` feeds Astro's Vite config (including the `astro:assets` virtual modules) into Vitest so components that import images don't break.

- [ ] **Step 4: Verify config loads**

```bash
pnpm test
```

Expected: "No test files found" (or similar — not an error about config or imports). If you see an error about `getViteConfig` not being exported, check your Astro version; the function was added in Astro 4.8.

- [ ] **Step 5: Commit**

```bash
git add package.json pnpm-lock.yaml vitest.config.ts
git commit -m "feat: add vitest with astro config"
```

### Task 4: Add GitHub Actions CI workflow

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create the workflow directory and file**

```bash
mkdir -p .github/workflows
```

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  ci:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 11.4.0

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build
        run: pnpm run build

      - name: Test
        run: pnpm test
```

- [ ] **Step 2: Verify the workflow file is valid YAML**

```bash
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))" && echo "Valid YAML"
```

Expected: `Valid YAML`

- [ ] **Step 3: Commit and push**


Then open the repository on GitHub → Actions tab and confirm the workflow appears and starts running.
